# 🛡️ OpenFGA — Сервис авторизации (ReBAC)

Полнофункциональная модель авторизации на основе отношений (**ReBAC — Relationship-Based Access Control**, архитектура Google Zanzibar) для организационной структуры предприятия: подразделения, штатное расписание, сотрудники, замещения, роли и персональные гранты/исключения.

Проект работает на **Node.js** с нативным клиентом OpenFGA (без Python и без внешних npm-зависимостей).

---

## 🚀 Быстрый старт

### 1. Запуск OpenFGA в Docker
```bash
docker compose up -d
```
OpenFGA запустится на порту `8088` (HTTP API) и `8081` (gRPC).

### 2. Загрузка модели и данных из CSV
```bash
npm run import
```
Скрипт создает хранилище (Store), компилирует `model.fga` и загружает кортежи отношений из 7 CSV-файлов директории `csv/`.

### 3. Запуск веб-интерфейса и API-сервера
```bash
# Порт по умолчанию — 3000 (или через переменную PORT)
PORT=8000 npm start
```
Откройте в браузере: **[http://localhost:8000](http://localhost:8000)** (или `http://localhost:3000`).

### 4. Запуск автотестов
```bash
npm test
```
Запускает **79 комплексных тестов** на нативном раннере `node:test` (17 групп проверок, 100% pass rate).

## 🧩 Ключевые возможности

### 1. Модель данных и сущности (7 типов)
- **`Employees` (Сотрудники)** — уникальные пользователи по табельному номеру / логину (`Employees:34491`).
- **`Divisions` (Подразделения)** — иерархическое дерево отделов с поддержкой неограниченной вложенности (`parent`, `child`, `descendant`, `ancestor`) и сквозных кодов склейки `full_code` (например, `755215147`).
- **`Staffs` (Штатные единицы)** — штатные позиции с привязкой к отделу и профессии (`Staffs:17363`).
- **`Professions` (Профессии / Должности)** — справочник должностей (`Professions:2104`).
- **`Roles` (Роли доступа)** — функциональные роли в корпоративных системах (`Roles:c66452e0-...`).
- **`Replacings` (Замещения)** — записи о временном исполнении обязанностей.
- **`Grants` (Гранты / Исключения)** — точечные персональные назначения ролей, отделов, штаток и профессий в обход стандартной оргструктуры.

### 2. Логика замещения сотрудников (Substitutions)
- **Одноуровневое замещение (`can_use_direct`)**: замещающий получает права строго 1-го уровня (своего непосредственного замещаемого сотрудника).
- **Транзитивная цепочка (`can_use_chain`)**: права передаются по всей цепочке замещений до последнего сотрудника (A замещает B, B замещает C ➔ A получает права C).
- **Симметричные связи**: модель поддерживает как прямой просмотр (`replaces` — кого замещает), так и обратный (`substitute` — кто замещает сотрудника).
- **Кадровый инвариант**: замещение наделяет сотрудника временными полномочиями управления (`can_use`), но **не меняет** его первичное кадровое прикрепление (`direct_employee` остается основным отделом).

### 3. Временный контекст (Contextual Tuples)
Симуляция разовых замещений и делегирования полномочий «на лету» без записи в базу данных. Временные кортежи передаются прямо в тело запроса `POST /check` (`contextual_tuples: [...]`) и учитываются ядром OpenFGA только в рамках текущей транзакции.

### 4. Интерактивный веб-интерфейс
- **⚡ 20 быстрых сценариев в 1 клик**: готовые кейсы проверок прямого доступа, замещений 1-го и 2-го уровней, блокировок, выборки отделов и contextual tuples.
- **🛡️ Форма Check API**: проверка любого отношения между субъектом и объектом с моментальным выводом компактного статуса `🟢 ALLOW` / `🔴 DENY`.
- **🔍 Зависимости (Lookup API)**: выборка всех связанных сущностей через `ListObjects` и `ListUsers` (все доступные отделы, подчиненные отделы, штатки, роли).
- **⚡ Пакетная проверка (BatchCheck)**: параллельное выполнение десятков проверок за 1 сетевой вызов к OpenFGA.
- **🕸️ Интерактивный граф**: визуализация схемы модели (7 сущностей) и цепочки разрешения прав (Data Path) в реальном времени.
- **📡 Инспектор API**: предпросмотр HTTP-запроса (Live Request Preview), готовые команды `cURL`, форматированный JSON запроса/ответа и замер latency (в миллисекундах).
- **📊 Просмотр таблиц**: интерактивная фильтрация всех 7 таблиц с подсчетом записей.

## 📡 Примеры API-запросов

### 1. Проверка права доступа (`POST /check`)
```bash
curl -X POST http://localhost:8000/check \
  -H "Content-Type: application/json" \
  -d '{
    "user": "Employees:34491",
    "relation": "can_use",
    "object": "Divisions:755"
  }'
```
**Ответ:**
```json
{
  "allowed": true,
  "durationMs": 5.2,
  "relation": "can_use"
}
```

### 2. Проверка с динамическим контекстом (`Contextual Tuples`)
Временное замещение сотрудника `68176` на лету (доступ к чужому отделу `787` без изменения БД):
```bash
curl -X POST http://localhost:8000/check \
  -H "Content-Type: application/json" \
  -d '{
    "user": "Employees:34491",
    "relation": "can_use",
    "object": "Divisions:787",
    "contextual_tuples": [
      { "user": "Employees:34491", "relation": "direct_substitute", "object": "Employees:68176" },
      { "user": "Employees:68176", "relation": "direct_replaces", "object": "Employees:34491" }
    ]
  }'
```

### 3. Получение списка доступных объектов (`POST /list-objects`)
Выборка всех подразделений (личных и замещаемых), доступных сотруднику:
```bash
curl -X POST http://localhost:8000/list-objects \
  -H "Content-Type: application/json" \
  -d '{
    "user": "Employees:34491",
    "relation": "all_divisions_chain",
    "type": "Divisions"
  }'
```

### 4. Пакетная проверка (`POST /batch-check`)
```bash
curl -X POST http://localhost:8000/batch-check \
  -H "Content-Type: application/json" \
  -d '{
    "checks": [
      {
        "correlation_id": "check-1",
        "tuple_key": { "user": "Employees:34491", "relation": "can_use", "object": "Divisions:755" }
      },
      {
        "correlation_id": "check-2",
        "tuple_key": { "user": "Employees:34491", "relation": "direct_employee", "object": "Divisions:755" }
      }
    ]
  }'
```

## 🧪 Тестирование и инварианты

Тестовый набор `test/test.js` проверяет следующие ключевые инварианты системы:
1. **Базовый доступ сотрудников**: прямое назначение роли, прямое подразделение, прямая штатка.
2. **Отношения 1:1**: у каждого сотрудника строго одно первичное подразделение и одна профессия.
3. **Иерархия подразделений**: корректная склейка `full_code`, подчиненность `child` / `descendant`.
4. **Замещение 1-го уровня vs. цепочка**:
   - `can_use_direct` разрешает доступ только к ресурсам первого замещаемого.
   - `can_use_chain` успешно транзитивно разрешает доступ через 2+ уровня замещений.
5. **Гранты и исключения**: корректный приоритет персональных назначений над оргструктурой.
6. **Contextual Tuples**: корректность динамического вычисления прав на лету без изменения постоянного хранилища.
7. **Пакетная обработка**: параллельное выполнение проверок через BatchCheck API.
